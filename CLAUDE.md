# updown-twap-bot

Python-бот (asyncio) для рынков Polymarket Up/Down на BTC/ETH (5m и 15m).
Идея: сравнивать вероятность исхода, оценённую по живому Chainlink TWAP,
с ценой на стакане и входить только при положительном edge ПОСЛЕ комиссий.

## Жёсткие правила

1. **По умолчанию DRY_RUN=1.** Реальные ордера возможны только если одновременно:
   `DRY_RUN=0` в окружении, `--live` в командной строке и существует файл `LIVE_OK`
   (его создаёт человек вручную). Иначе бот работает только через `PaperBroker`.
2. **Секреты.** Приватный ключ и API-ключи только из переменных окружения. Не логировать,
   не коммитить. `.env` и `*.db` в `.gitignore`. Для live предполагается отдельный кошелёк
   с небольшой суммой.
3. **Не выдумывать API.** Перед написанием кода интеграции прочитай актуальную документацию:
   начни с https://docs.polymarket.com/llms.txt. Названия топиков, клиентов и символов
   из статей и из моего черновика могут быть устаревшими. Известно, что в документации
   есть страница миграции RTDS -> PolyBolt, где символы (`btc/usd` vs `btcusd`) и топики
   отличаются. Выясни, что актуально сейчас, и опиши в `docs/API_NOTES.md` с ссылками.
   Если что-то нельзя проверить, оставь интерфейс и `TODO(verify)`, а не догадку.
4. **Комиссии обязательны в расчёте.** На 5m и 15m крипторынках есть taker-комиссия
   (по публикациям около 3% от суммы вблизи цены 0.50, меньше у краёв) и maker-rebate.
   Точную формулу возьми из документации, реализуй `fees.py` с тестами на примеры из доков.
   Любой расчёт edge и PnL идёт после комиссий; maker-исполнение комиссии не платит.
5. **Нет молчаливых сбоев.** RTDS-сокет может «зависнуть» без разрыва соединения.
   Хранить `last_data_ts`; если данных нет дольше порога (стартово 45 с, настраивается),
   переподключиться и не открывать новые позиции, пока цена не станет свежей.

## Модули (уже есть: `twap_signal.py`, `store.py`; не переписывать без причины)

| Файл | Назначение |
|---|---|
| `feed.py` | подписка на TWAP (и спот-цену Binance/Coinbase для sigma), heartbeat, reconnect |
| `markets.py` | поиск активных 5m/15m рынков, strike (price to beat), время расчёта, token_id Up/Down |
| `book.py` | стакан CLOB: лучшие цены, глубина, свежесть |
| `twap_signal.py` | edge по модели (готов; см. оговорки ниже) |
| `fees.py` | taker-комиссия и rebate по документации |
| `broker.py` | интерфейс `Broker`; `PaperBroker` и `ClobBroker` |
| `exits.py` | тейк-профит, стоп, выход по времени/близости к расчёту |
| `risk.py` | профили риска, лимиты, kill switch |
| `store.py` | SQLite: позиции из журнала ордеров и сделок, `reconcile()` при старте |
| `report.py` | метрики и отчёт по бумажной торговле |
| `main.py` | asyncio-цикл, запуск и остановка |

Оговорки к `twap_signal.py`: волатильность считается по принтам TWAP и занижена,
поэтому sigma лучше брать со спот-фида; `cost` и `min_edge` нужно калибровать на записанных данных.

## Профили риска (`config.toml`)

Три профиля: `conservative`, `moderate`, `aggressive`. Каждый задаёт: `min_edge`,
размер позиции, максимум одновременных позиций, дневной лимит убытка, стоп, минимальную
глубину стакана, максимальный спред. Дневной лимит убытка закрывает новые входы до следующего дня.

## Исполнение

- Вход: сначала пробовать maker (лимитный, не пересекающий спред), если edge это позволяет;
  taker только если edge после комиссии всё ещё выше порога.
- Тейк-профит: лимитный ордер.
- Стоп: агрессивный лимитный ордер, пересекающий спред, с нижней границей цены.
  Лимитный стоп по рыночной цене не годится: в тонком стакане он не исполнится.
- Выходы реагируют на события из потока, а не опрашивают раз в минуту.
- Альтернатива выходам: держать до расчёта. Реализуй как опцию и сравни в отчёте.
- Один рынок: не больше одной незакрытой позиции (уже защищено индексом в `store.py`).

## PaperBroker должен быть консервативным

- Покупка исполняется только по ask, продажа по bid, и только на доступном объёме стакана.
- Комиссия и проскальзывание учитываются; задержка между сигналом и исполнением настраивается.
- Никаких исполнений «по mid» и по цене, которой уже нет на стакане.

## Данные и метрики

- Писать в JSONL каждый тик признаков, снимки стакана при сигнале, все решения (включая отказы с причиной).
  Это нужно для воспроизведения (replay) и калибровки.
- Главные метрики: средний PnL на сделку после комиссий (expectancy) с доверительным интервалом,
  калибровка (предсказанная p_fair против реальных исходов), PnL по часам, по окнам 5m/15m, по профилям.
  Win rate сам по себе ничего не доказывает, показывать его только рядом со средним выигрышем и средним проигрышем.

## Критерий перехода к live (предложение, решает человек)

- Не меньше 200 закрытых бумажных сделок на каждый профиль, который хотим запускать.
- Положительный средний PnL после комиссий, нижняя граница доверительного интервала не сильно ниже нуля.
- Калибровка без систематического смещения.
- Первый live: минимальный размер и жёсткий дневной лимит убытка.

## Тесты и порядок работы

- `pytest`; обязательные тесты: сигнал, комиссии, `store` (дубли сделок, частичные исполнения, `reconcile`),
  `PaperBroker` (исполнение по стакану), логика выходов на синтетических сценариях.
- Работать вехами: M1 каркас и feed, M2 markets и book, M3 бумажный цикл целиком, M4 отчёт и replay,
  M5 `ClobBroker` (только после того, как M1-M4 приняты человеком).
- После каждой вехи: что сделано, что проверено, что не проверено, что нужно от человека.
